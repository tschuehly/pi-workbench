# Routing rationale and calibration

The authoritative current role-to-binding mapping lives in `routing-policy.json`. These bindings
graduated as a provisional Pi adapter from the skill-incubator policy; evaluate them from Workbench
run evidence rather than treating them as permanent model ownership. The router resolves one binding per invocation from Cognitive Role, author model family, and any
reviewer-family exclusions. The lead still sizes and assembles the checking panel; Alignment remains
a separate commitment boundary, not a mutation gate.

GPT-6 Sol handles implementation, problem-solving, and coordination. GPT-6 Luna handles design, escalation, investigation, and mechanics. Higher Model Effort follows novelty and consequence rather than code volume; maximum effort remains exceptional because marginal quality can consume disproportionate quota.

Astra is an explicit owner-requested override, not a default binding. Use it for long-horizon coordination, difficult engineering or migration work, consequential computer/browser operation, and high-context escalation. Astra is in the same OpenAI family as Sol and Luna and supplies no independent review. See [`gpt-6-astra-strengths.md`](../../../docs/research/reports/gpt-6-astra-strengths.md).

Claude capacity is reserved for specialist value: Fable judges or challenges OpenAI-authored work; Opus 5.5 synthesizes system models or reviews high-risk OpenAI-authored diffs. When the author uses Anthropic, independent judgment and challenge route to Luna, while independent review routes to Sol. Cross-family selection follows the recorded author model's underlying family, including models hosted by GitHub Copilot. Family diversity supplies Independence, not correctness, and claims still require Primary Evidence.

Terra remains an execution calibration candidate rather than a normal fallback. Owner-requested Astra or Fable one-shots go through `subagent`; Workers are for repeated assignments whose stable semantic scope benefits from continuity. The independent-role candidate lists include `github-copilot/grok-4.6` to make a distinct non-author-family panel selectable through exclusions. This is a routing capability, not a quality ranking. Compare judges using role, task shape, challenge lens, Model Effort, quota windows, outcome evidence, corrections, elapsed time, and any redo by another model. Other catalog families are recognized for author identity but gain no reviewer binding merely by being listed.
