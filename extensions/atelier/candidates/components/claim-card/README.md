# claim-card

**Pick:** a changed behavior needs a human exercise, not a selector-presence check.
**Lesson:** Before/Now → reachable setup → numbered exercise → Expected → observed result. Locating a
control, having the scenario available, and verifying its behavior are three different claims.

**Why:** the earlier composition was judged strongest, but six confirmations were made against a 404;
Confirm/Redo sufficed and Reset did not ([LAU via WC T2/§3](../../SOURCES.md)). ME asked for quote + Expected
“always” (O L2711/L2849); that does not settle a new manual-run product mode.

**Use:** [example.html](example.html) contrasts an unavailable scenario (no Verdict) with an exercisable
local text field. Add `atl-verdict="Confirm|Redo"` only where the scenario can be exercised; name the build
in `atl-ver`. Pair with review-bridge for location only, or grade-axes for multiple dimensions.
**Limit:** Kernel has no required Redo note; a separate Comment is not atomic. Absorbs scenario-readiness.
**Skip:** a proposed change not implemented yet; use a Kernel Decision on the proposal instead.
