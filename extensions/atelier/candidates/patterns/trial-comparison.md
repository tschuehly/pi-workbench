# Compare trial outcomes

Candidate Pattern · WC · Owner-spec. An offered arrangement, not a Registry admission or
content rule (107/117). Choose and change it for the task; no prescribed word count or page schema.

## When it helps
Compare genuine alternative apps without losing which revision each observed outcome belongs to.

## Components and hierarchy
1. [variant-picker](../components/variant-picker/README.md) names the trial and its deep link; [viewport-frame](../components/viewport-frame/README.md) opens its live app.
2. [claim-card](../components/claim-card/README.md) and [scenario-readiness](../components/scenario-readiness/README.md) turn flagged untested spots into explicit checks.
3. [named-flow](../components/named-flow/README.md), [attempt-timeline](../components/attempt-timeline/README.md) and [source-reference](../components/source-reference/README.md) explain each trial stage and handoff.
4. [cost-ledger](../components/cost-ledger/README.md) supplies measured resource use; [decision-context](../components/decision-context/README.md) asks which change or trial to keep.

## Kernel / Keys
Trial/stage/claim Keys + build revision. Adoption Decisions sit on change rows, including rejected fixes when the owner still has a choice. Other Requests/jobs retain their Kernel lifecycle.

## Evidence for and against
[WC §2 T2/T3/T5/T6](../SOURCES.md#use-cases): four apps, Today/Proposed/Evidence rows, keep/change/retire. No four-app judging observed at cutoff. Anonymous judging before costs was a judge suggestion, not an owner decision.

## Boundaries
One-at-a-time is a starting option, not a prohibition on real side-by-side comparison. Blind labels and delayed cost reveal are offered only if chosen for the actual trial. Rebase never silently updates pinned report evidence.
