# Subagent extension

Level 1's attended `subagent` tool. One invocation accepts `task`, a bundled `profile`, a `cognitiveRole`, optional `independentOfProvider`, and an optional `background` flag; it resolves a fresh provider/model/effort binding through Workbench model-orchestration policy and delegates process lifecycle to `packages/pi-execution-adapter/`.

When `background` is omitted, the tool streams progress and blocks until the child finishes. Decision 99 makes `background: true` the system-prompt preference for most delegated Subagents and Worker dispatches so the attended lead remains available; foreground blocking is reserved for an immediate dependency when no useful lead work or attended response can continue. With `background: true` the tool returns a handle immediately so the lead can launch children and keep working. When that child reaches a terminal outcome, the extension sends the attended lead one deduplicated, bounded `followUp` wakeup and asks it to collect and reconcile exactly once. The wakeup contains identity and outcome only; the terminal result remains behind `subagent_collect`. An active collection suppresses a not-yet-sent wakeup, re-arms it if collection detaches before terminal, and permanently handles it after terminal reconciliation. Explicit cancellation and `session_shutdown` suppress late wakeups while cancelling live children. Three companion tools reconcile backgrounded children within the same session: `subagent_status` (non-blocking snapshot of one child or a list of all), `subagent_collect` (stream remaining progress and return the compact terminal result), and `subagent_cancel` (cancel and confirm termination). Backgrounding is in-session only: children still die on `session_shutdown` and receive no durable identity, recovery, or unattended lifetime. Durable, unattended background execution remains deferred to the controller.

Bundled profiles are `scout`, `planner`, `reviewer`, and `implementer`. Profiles select child behavior and requested tools independently from the Cognitive Role used for model and Model Effort routing; any known role may be paired with any bundled profile. For `independent-judgment`, `challenge`, and `independent-review`, routing selects a different provider family from `independentOfProvider`, which defaults to the active parent provider and can be set to the actual author provider for child-authored work. Requested tools are intersected with the adapter's host ceiling. User/project profiles, static model fields, batches, chains, retries, transcript forks, and durable background execution that survives the session are intentionally unsupported.

Four worker tools add durable attended workers beside the ephemeral subagent, per [`docs/plans/level-1-durable-workers.md`](../../docs/plans/level-1-durable-workers.md). `worker_create` records a machine-local identity (name, one semantic scope, bundled profile, bound repository root) in `packages/worker-registry/` and starts no process. `worker_dispatch` runs one bounded attended assignment with the same lifecycle as `subagent`, resuming the worker's persisted Pi session for continuity; each dispatch still resolves a fresh binding by Cognitive Role, and Independence roles are rejected because independence requires fresh context. One dispatch at a time per worker: a busy worker fails preflight, terminal outcomes release the lock before any completion wakeup is sent, a background receipt-settlement failure emits separately deduplicated bounded `outcome_unknown` attention without claiming lock release, while a foreground failure returns an `outcome_unknown` tool result with the child result marked inspection-only, an `outcome_unknown` dispatch requires `acknowledgeInspection` before the next one, and a dead lock owner is reclaimed only after liveness verification. `worker_status` inspects records plus any live dispatch; `worker_retire` is immutable. Worker identity survives the attended session; execution never does, and no Run authority or managed recovery is implied.

The child uses a fresh, machine-local persistent Pi RPC session (or the worker's resumed session). In interactive Pi, `⌘B` (or `Ctrl+Alt+B`) moves the newest foreground Subagent or Worker into the background without cancelling it, using the same terminal wakeup and reconciliation flow as `background: true`; `⌘B` requires a terminal that forwards the Command/Super modifier. Every active dispatch publishes to the shared **Active** surface above the editor. Width-aware, single-line pills pack horizontally and wrap as units. Each pill leads with mechanically normalized current activity, protects model and Model Effort metadata, and adds compact `🤖` Subagent or `🧰` Worker identity and Cognitive Role when width permits; the launch objective is omitted. The pill disappears when execution ends. While the parent waits, the foreground tool additionally renders a bounded rolling activity log with elapsed time, recent normalized lifecycle/tool events, and a periodic last-activity refresh. Raw thinking content is never shown. Cancellation is confirmed through process termination, and the parent receives only the compact terminal result and session metadata. This grants no managed Run authority, durable actor identity, workspace isolation, recovery, acceptance, or publication right.
