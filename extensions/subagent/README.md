# Subagent extension

Level 1's attended `subagent` tool. One invocation accepts `task`, a bundled `profile`, a `cognitiveRole`, optional author provider or exact author model, and an optional `background` flag; it resolves a fresh provider/model/effort binding through Workbench model-orchestration policy and delegates process lifecycle to `packages/pi-execution-adapter/`.

When `background` is omitted, the tool streams progress and blocks until the child finishes. Decision 99 makes `background: true` the system-prompt preference for most delegated Subagents and Worker dispatches so the attended lead remains available; foreground blocking is reserved for an immediate dependency when no useful lead work or attended response can continue. With `background: true` the tool returns a handle immediately so the lead can launch children and keep working. When a background child reaches a terminal outcome, the extension sends the attended lead one generic bounded `steer` signal that reaches it at the next safe model boundary, and asks it to call `subagent_status` and then collect and reconcile each terminal-uncollected child exactly once. The signal names no execution and carries no result; everything stays behind `subagent_collect`. Further completions send nothing while that signal is outstanding: delivery of that exact message, or a settled agent, re-arms attention, and only a new completion signals again. There is no second reminder loop. An active collection suppresses a not-yet-sent wakeup, re-arms it if collection detaches before terminal, and permanently handles it after terminal reconciliation. Explicit cancellation and `session_shutdown` suppress late wakeups while cancelling live children. Three companion tools reconcile backgrounded children within the same session: `subagent_status` (non-blocking snapshot of one child or a list of all), `subagent_collect` (stream remaining progress and return the compact terminal result), and `subagent_cancel` (cancel and confirm termination). Backgrounding is in-session only: children still die on `session_shutdown` and receive no durable identity, recovery, or unattended lifetime. Durable, unattended background execution remains deferred to the controller.

Bundled profiles are `scout`, `planner`, `reviewer`, and `implementer`. Profiles select child behavior and requested tools independently from the Cognitive Role used for model and Model Effort routing; any known role may be paired with any bundled profile. For `independent-judgment`, `challenge`, and `independent-review`, `independentOfModel` may always quote the exact author from a completion receipt: default routing uses its provider to select a different family, while an active single-provider overlay uses the exact model to select a different allowed model. Without either author parameter, routing defaults to the active parent provider. Requested tools are intersected with the adapter's host ceiling. User/project profiles, static model fields, batches, chains, retries, transcript forks, and durable background execution that survives the session are intentionally unsupported.

Four worker tools add durable attended workers beside the ephemeral subagent, per [`docs/plans/level-1-durable-workers.md`](../../docs/plans/level-1-durable-workers.md). `worker_create` records a machine-local identity (owning lead session, name, one semantic scope, bundled profile, bound repository root) in `packages/worker-registry/` and starts no process. `worker_dispatch` runs one bounded attended assignment with the same lifecycle as `subagent`, resuming the worker's persisted Pi session for continuity; each dispatch still resolves a fresh binding by Cognitive Role, and Independence roles are rejected because independence requires fresh context. One dispatch at a time per worker: a busy worker fails preflight, terminal outcomes release the lock before any completion signal is sent, a background receipt-settlement failure emits separately deduplicated bounded per-execution `outcome_unknown` attention that never merges with or clears the coalesced signal and claims no lock release, while a foreground failure returns an `outcome_unknown` tool result with the child result marked inspection-only, an `outcome_unknown` dispatch requires `acknowledgeInspection` before the next one, and a dead lock owner is reclaimed only after liveness verification. Workers require and are owned by the persisted lead Pi session that creates them: dispatch and retirement reject foreign sessions (including forks and new sessions), while the first mutation claims a legacy unowned record, and `worker_status` lists only that session's active workers by default. `worker_status { all: true }` exposes all machine-local records, including retired and foreign-session workers, for diagnostics. Worker identity survives reloads and process restarts of its owning persisted session; execution never survives session shutdown, and no Run authority or managed recovery is implied.

The child uses a fresh, machine-local persistent Pi RPC session (or the worker's resumed session). In interactive Pi, `⌘B` (or `Ctrl+Alt+B`) moves the newest foreground Subagent or Worker into the background without cancelling it, using the same coalesced completion signal and reconciliation flow as `background: true`; `⌘B` requires a terminal that forwards the Command/Super modifier. Every active dispatch publishes to the shared **Active** surface above the editor. Width-aware, single-line pills pack horizontally and wrap as units. Each pill leads with mechanically normalized current activity, protects model and Model Effort metadata, and adds compact `🤖` Subagent or `🧰` Worker identity and Cognitive Role when width permits; the launch objective is omitted. The pill disappears when execution ends. While the parent waits, the foreground tool additionally renders a bounded rolling activity log with elapsed time, recent normalized lifecycle/tool events, and a periodic last-activity refresh. Raw thinking content is never shown. Cancellation is confirmed through process termination, and the parent receives only the compact terminal result and session metadata. This grants no managed Run authority, durable actor identity, workspace isolation, recovery, acceptance, or publication right.
