# Working Mode guidance conflicts: bounded audit

**Scope (2026-09-24):** Compare the [proposed four-axis text](working-mode-target-context-brief-2026-09-24.md) and its [source module](../../../extensions/agent-audit/working-mode-candidate.ts) at `2c7f71f6772a30c317f07dce7a29c480d837e598` with Pi's saved base prompt from preview set `92eb1ff5-d367-41a5-b285-61c4e7baac65`, the current global `~/.pi/agent/AGENTS.md` (SHA-256 `bbfe0746…`), current repository `AGENTS.md` at `9fccb54f44df2393da732b7e5a5fc15c286acc53`, and the implemented `extensions/working-mode/index.ts`. The preview's base came from Pi 0.84.3 on 2026-09-09; the current instructions and Pi installation have changed. This is a source-text compatibility audit, **not** a captured-request or model-behavior result. It cannot establish compatibility with instructions in future repositories.

A conflict here means two instructions could demand incompatible actions in the same situation. A conditional tension means the text permits a misleading interpretation but can be followed consistently if its boundary is made clear. A gap means a proposed behavior has no complete current mechanism or accepted policy. The saved Pi base tells a coding assistant to use `read`, `bash`, `edit`, and `write`, stay concise, and load Pi docs for Pi topics; none of the four candidate axes contradicts those base/tool instructions. The substantive overlaps begin in global and repository guidance and the older Working Mode suffix. Skill names and descriptions are advertised, but full skill bodies are not part of this saved base.
